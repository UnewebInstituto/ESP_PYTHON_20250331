¡Excelente pregunta\! En Django, no añades el atributo `UNIQUE` directamente en la "definición de una tabla" en el sentido de SQL puro dentro del ORM. En su lugar, lo especificas en la definición de tu modelo de Django, y el ORM se encarga de generar la sentencia SQL `CREATE TABLE` (o `ALTER TABLE`) adecuada con la restricción `UNIQUE` en PostgreSQL (o en la base de datos que estés usando).

Hay dos formas principales de hacerlo, dependiendo de si quieres que la unicidad sea para un solo campo o para una combinación de campos.

### 1\. Unicidad en un Solo Campo (Most Common)

Para hacer que un campo individual sea único, simplemente añades `unique=True` a la definición del campo en tu modelo.

**Ejemplo:**
Imagina que tienes un modelo `Producto` y quieres asegurarte de que cada producto tenga un código SKU único.

```python
# models.py

from django.db import models

class Producto(models.Model):
    nombre = models.CharField(max_length=200)
    # Este campo será único en la base de datos
    sku = models.CharField(max_length=50, unique=True)
    precio = models.DecimalField(max_digits=10, decimal_places=2)
    descripcion = models.TextField(blank=True)

    def __str__(self):
        return self.nombre

```

**Cómo funciona:**

  * Cuando ejecutes `python manage.py makemigrations` y luego `python manage.py migrate`, Django generará una migración que incluirá una restricción `UNIQUE` en la columna `sku` de la tabla `producto` en PostgreSQL.
  * Si intentas guardar dos objetos `Producto` con el mismo valor en el campo `sku`, Django (a través de la base de datos) lanzará una excepción `django.db.utils.IntegrityError`.

### 2\. Unicidad en una Combinación de Campos (UniqueTogether Constraint)

A veces, la unicidad no reside en un solo campo, sino en la combinación de dos o más campos. Por ejemplo, en un modelo `Inscripcion`, una persona solo puede estar inscrita una vez a un curso específico, pero puede estar inscrita a varios cursos, y varios cursos pueden tener la misma persona inscrita (solo que no para el mismo curso).

Para esto, usas la opción `unique_together` dentro de la clase `Meta` de tu modelo.

**Ejemplo:**
Supongamos un modelo `Inscripcion` donde una persona (estudiante) solo puede inscribirse una vez a un curso específico.

```python
# models.py

from django.db import models

class Estudiante(models.Model):
    nombre = models.CharField(max_length=100)
    email = models.EmailField(unique=True) # El email de un estudiante debe ser único

    def __str__(self):
        return self.nombre

class Curso(models.Model):
    titulo = models.CharField(max_length=200)
    codigo_curso = models.CharField(max_length=20, unique=True) # El código del curso debe ser único

    def __str__(self):
        return self.titulo

class Inscripcion(models.Model):
    estudiante = models.ForeignKey(Estudiante, on_delete=models.CASCADE)
    curso = models.ForeignKey(Curso, on_delete=models.CASCADE)
    fecha_inscripcion = models.DateField(auto_now_add=True)

    class Meta:
        # Esto asegura que la combinación de 'estudiante' y 'curso' sea única.
        # Un estudiante no puede inscribirse al mismo curso dos veces.
        unique_together = ('estudiante', 'curso')
        verbose_name = "Inscripción"
        verbose_name_plural = "Inscripciones"

    def __str__(self):
        return f"{self.estudiante.nombre} - {self.curso.titulo}"

```

**Cómo funciona:**

  * `unique_together = ('estudiante', 'curso')`: Le dice a Django que la combinación de los valores de los campos `estudiante` y `curso` debe ser única en toda la tabla `inscripcion`.
  * Al ejecutar `makemigrations` y `migrate`, Django creará una restricción `UNIQUE` compuesta en la base de datos que abarcará ambas columnas.
  * Si intentas crear una `Inscripcion` donde ya existe un `estudiante` y un `curso` idénticos, obtendrás una `IntegrityError`.

### Consideraciones adicionales:

  * **Django 3.x+ y `UniqueConstraint`:** A partir de Django 3.0, `unique_together` es funcional, pero la forma preferida y más flexible de definir restricciones de unicidad compuestas (y otras restricciones de base de datos) es a través de la clase `Meta.constraints` usando `models.UniqueConstraint`.
