Para saber si un módulo está instalado en tu entorno virtual, tienes varias formas de verificarlo, cada una con sus propias ventajas. Aquí te presento las más comunes y efectivas, asumiendo que ya tienes tu entorno virtual activado:

### 1\. Usando `pip list`

Esta es la forma más directa y recomendada para ver todos los paquetes instalados en tu entorno actual (sea virtual o global).

**Pasos:**

1.  **Activa tu entorno virtual:**

      * En Windows: `.\nombre_de_tu_entorno\Scripts\activate`
      * En macOS/Linux: `source nombre_de_tu_entorno/bin/activate`

2.  **Ejecuta `pip list`:**

    ```bash
    pip list
    ```

    Esto te mostrará una lista de todos los paquetes instalados junto con sus versiones. Puedes escanear la lista para encontrar el módulo que buscas.

3.  **Para buscar un módulo específico (filtrado):**
    Puedes combinar `pip list` con herramientas de filtrado de la línea de comandos:

      * En Windows (PowerShell/CMD):
        ```bash
        pip list | findstr "nombre_del_modulo"
        ```
      * En macOS/Linux (Bash/Zsh):
        ```bash
        pip list | grep "nombre_del_modulo"
        ```

    Si el módulo está instalado, aparecerá en la salida. Si no aparece, es probable que no esté instalado en ese entorno.

### 2\. Usando `pip show`

Si sabes el nombre exacto del módulo que buscas, `pip show` te dará información detallada sobre él, incluyendo si está instalado y dónde.

**Pasos:**

1.  **Activa tu entorno virtual.**

2.  **Ejecuta `pip show nombre_del_modulo`:**

    ```bash
    pip show requests
    ```

    (Reemplaza `requests` por el nombre del módulo que buscas, por ejemplo `numpy`, `pandas`, etc.)

    **Resultados posibles:**

      * **Si el módulo está instalado:** Verás información detallada como la versión, la ubicación de instalación, los requisitos, etc.
        ```
        Name: requests
        Version: 2.31.0
        Summary: Python HTTP for Humans.
        Home-page: https://requests.readthedocs.io
        Author: Kenneth Reitz
        Author-email: me@kennethreitz.org
        License: Apache 2.0
        Location: C:\Users\TuUsuario\proyectos\mi_entorno_virtual\lib\site-packages
        Requires: charset-normalizer, idna, urllib3, certifi
        Required-by:
        ```
        Fíjate en la línea `Location:`, que debería apuntar a la ruta de tu entorno virtual (`...mi_entorno_virtual\lib\site-packages` o similar).
      * **Si el módulo no está instalado:** Obtendrás un mensaje de error indicando que el paquete no fue encontrado.
        ```
        WARNING: Package(s) not found: non_existent_module
        ```

### 3\. Intentando importarlo desde el intérprete de Python

Esta es una forma más programática de verificarlo y es útil si quieres comprobar la disponibilidad del módulo dentro de un script.

**Pasos:**

1.  **Activa tu entorno virtual.**

2.  **Inicia el intérprete de Python:**

    ```bash
    python
    ```

3.  **Intenta importar el módulo:**

    ```python
    import nombre_del_modulo
    ```

    (Por ejemplo, `import requests`)

    **Resultados posibles:**

      * **Si el módulo está instalado:** No verás ningún error y el prompt de Python (`>>>`) volverá. Esto significa que Python pudo encontrar y cargar el módulo.
      * **Si el módulo no está instalado:** Obtendrás un `ModuleNotFoundError`.
        ```python
        >>> import non_existent_module
        Traceback (most recent call last):
          File "<stdin>", line 1, in <module>
        ModuleNotFoundError: No module named 'non_existent_module'
        ```
      * **Para salir del intérprete:**
        ```python
        exit()
        ```

### 4\. Verificando la ruta de los paquetes (Sys.path)

Cuando un entorno virtual está activado, la variable `sys.path` de Python se modifica para incluir el directorio `site-packages` de ese entorno.

**Pasos:**

1.  **Activa tu entorno virtual.**
2.  **Inicia el intérprete de Python.**
3.  **Verifica `sys.path` y la ubicación de tu entorno:**
    ```python
    import sys
    print(sys.path)
    import os

    # Ruta esperada para site-packages dentro del entorno virtual
    # Esto es un ejemplo, adapta 'mi_entorno_virtual' al nombre real de tu entorno
    # y la estructura de directorios
    expected_site_packages_path = os.path.join(os.getcwd(), 'mi_entorno_virtual', 'Lib', 'site-packages')
    # O para Unix/macOS:
    # expected_site_packages_path = os.path.join(os.getcwd(), 'mi_entorno_virtual', 'lib', 'pythonX.Y', 'site-packages')
    # donde X.Y es tu versión de Python (ej. python3.9)

    print(f"¿La ruta de mi entorno virtual está en sys.path? {expected_site_packages_path in sys.path}")
    ```
    Aunque `sys.path` te dice si tu entorno virtual está activo y dónde buscaría Python los módulos, no te dice directamente si un *módulo específico* está instalado. Para eso, es mejor `pip list`, `pip show` o el `import`.

### Consideraciones importantes:

  * **¡Siempre activa tu entorno virtual primero\!** Si no lo activas, `pip list` y `pip show` te mostrarán los paquetes instalados globalmente o en el entorno base de tu sistema, no en tu entorno virtual.
  * **Diferencia entre entorno virtual y entorno global:** Los módulos instalados en tu entorno virtual son *aislados* y no afectan a otras instalaciones de Python en tu sistema, y viceversa.
  * **Nombre del módulo vs. nombre del paquete PyPI:** A veces, el nombre que usas para importar un módulo en Python (ej. `import bs4` para Beautiful Soup) es diferente del nombre del paquete en PyPI que instalas con `pip` (ej. `pip install beautifulsoup4`). `pip list` y `pip show` usan el nombre del paquete PyPI. Si no estás seguro, busca el módulo en PyPI.org para ver su nombre oficial de paquete.

Elige el método que mejor se adapte a tu necesidad en el momento. Generalmente, `pip list` y `pip show` son las opciones más robustas para una verificación rápida.

### Exportar a CSV

Para exportar a CSV, la forma más directa y recomendada es usar el comando `COPY` de PostgreSQL. Este comando se ejecuta desde la interfaz de `psql` (la línea de comandos de PostgreSQL) o directamente desde tu aplicación cliente.

El comando `COPY` exporta los datos directamente desde el servidor de PostgreSQL a un archivo en el sistema de archivos del servidor (si usas `TO '/ruta/archivo.csv'`) o al sistema de archivos del cliente que ejecuta `psql` (si usas `\copy`). Dado que quieres la exportación en una ruta local de tu máquina cliente (`C:\`), **debemos usar `\copy`**.

```sql
-- Primero, asegúrate de que estás conectado a la base de datos 'bd_nivel2_henry'
-- desde tu cliente psql.

-- Genera la fecha y hora actual en el formato deseado
SELECT TO_CHAR(NOW(), 'YYYYMMDD_HH24MISS');

-- Usa el comando \copy para exportar a CSV
-- La ruta debe existir previamente en tu sistema.
\copy (SELECT id, cedula, nombre, apellido, direccion, fechanac FROM persona_individuos) TO 'C:/ESP_PYTHON_20250331/NIVEL_V/HENRY/excel/persona_' || TO_CHAR(NOW(), 'YYYYMMDD_HH24MISS') || '.csv' WITH (FORMAT CSV, HEADER, DELIMITER ',');
```

**Explicación del comando:**

  * **`\copy`**: Este es el meta-comando de `psql` que permite exportar datos desde el servidor PostgreSQL al *sistema de archivos local del cliente* donde estás ejecutando `psql`. Es crucial para que el archivo termine en tu `C:\` drive.
  * **`(SELECT id, cedula, nombre, apellido, direccion, fechanac FROM persona_individuos)`**: Aquí especificamos la consulta SQL cuyos resultados queremos exportar. He listado explícitamente las columnas para asegurar el orden y la selección deseada, aunque `SELECT *` también funcionaría si quieres todas las columnas en su orden predeterminado.
  * **`TO 'C:/ESP_PYTHON_20250331/NIVEL_V/HENRY/excel/persona_' || TO_CHAR(NOW(), 'YYYYMMDD_HH24MISS') || '.csv'`**:
      * Esta es la ruta completa donde se guardará el archivo CSV.
      * **Importante**: En Windows, las barras inclinadas (`/`) son generalmente preferibles en rutas dentro de cadenas SQL, aunque las barras invertidas (`\`) escapadas (`\\`) también funcionan.
      * `'persona_' || TO_CHAR(NOW(), 'YYYYMMDD_HH24MISS') || '.csv'` es una concatenación de strings para construir el nombre de archivo dinámico.
          * `TO_CHAR(NOW(), 'YYYYMMDD_HH24MISS')` formatea la fecha y hora actuales (`NOW()`) al formato `AAAAMMDD_HHMMSS` (utilizando `HH24` para el formato de 24 horas).
  * **`WITH (FORMAT CSV, HEADER, DELIMITER ',')`**: Estas son las opciones de formato para el archivo CSV:
      * `FORMAT CSV`: Especifica que el formato de salida es CSV.
      * `HEADER`: Incluye una fila de encabezado con los nombres de las columnas en el archivo CSV.
      * `DELIMITER ','`: Define la coma como el separador de campos.

```python
import psycopg2
import pandas as pd
from datetime import datetime
import os

# --- Configuración de la base de datos ---
DB_HOST = "localhost"
DB_NAME = "bd_nivel2_henry"
DB_USER = "tu_usuario"  # <--- CAMBIA ESTO por tu usuario de PostgreSQL
DB_PASSWORD = "tu_password" # <--- CAMBIA ESTO por tu contraseña de PostgreSQL
DB_PORT = "5432"

# --- Configuración de la exportación ---
EXPORT_DIR = r"C:\ESP_PYTHON_20250331\NIVEL_V\HENRY\excel" # La 'r' es para raw string, evita problemas con barras invertidas
TABLE_NAME = "persona_individuos"
OUTPUT_FILENAME_BASE = "persona"

def export_to_excel():
    """
    Exporta la tabla persona_individuos de PostgreSQL a un archivo Excel (.xlsx)
    con un nombre de archivo dinámico basado en la fecha y hora.
    """
    try:
        # Crea la ruta de exportación si no existe
        os.makedirs(EXPORT_DIR, exist_ok=True)

        # Genera el nombre del archivo con la fecha y hora actuales
        current_datetime = datetime.now()
        timestamp = current_datetime.strftime("%Y%m%d_%H%M%S")
        output_filename = f"{OUTPUT_FILENAME_BASE}_{timestamp}.xlsx"
        output_filepath = os.path.join(EXPORT_DIR, output_filename)

        print(f"Conectándose a la base de datos '{DB_NAME}'...")
        conn = psycopg2.connect(
            host=DB_HOST,
            database=DB_NAME,
            user=DB_USER,
            password=DB_PASSWORD,
            port=DB_PORT
        )
        print("Conexión exitosa.")

        # Consulta para seleccionar todos los datos de la tabla
        query = f"SELECT id, cedula, nombre, apellido, direccion, fechanac FROM {TABLE_NAME};"

        print(f"Cargando datos de la tabla '{TABLE_NAME}'...")
        # Usa pandas para leer los datos directamente de PostgreSQL
        df = pd.read_sql_query(query, conn)
        print(f"Datos cargados. Filas: {len(df)}")

        # Guarda el DataFrame en un archivo Excel
        print(f"Exportando datos a: {output_filepath}")
        df.to_excel(output_filepath, index=False) # index=False para no escribir el índice de pandas
        print("Exportación a Excel completada exitosamente.")

    except psycopg2.Error as e:
        print(f"Error de base de datos: {e}")
    except Exception as e:
        print(f"Ocurrió un error: {e}")
    finally:
        if 'conn' in locals() and conn:
            conn.close()
            print("Conexión a la base de datos cerrada.")

if __name__ == "__main__":
    export_to_excel()
```

**Pasos para ejecutar el script de Python:**

1.  **Guarda el código** anterior como `exportar_excel.py`.

¡Ah, el famoso `No module named 'openpyxl'`\! Este es un error muy común y, afortunadamente, tiene una solución directa.

-----

### Causa del Error

El mensaje de error `Ocurrió un error: No module named 'openpyxl'` significa que el módulo **`openpyxl` no está instalado** en el entorno de Python donde se está ejecutando tu aplicación Django.

Aunque tú has instalado `pandas`, y `pandas` es capaz de trabajar con archivos Excel, para **escribir** en el formato `.xlsx` (el formato de Excel más moderno), `pandas` no lo hace por sí mismo. Necesita una "biblioteca de motor" o "backend" para manejar la complejidad del formato XLSX. El módulo **`openpyxl`** es la biblioteca recomendada por `pandas` para esta tarea.

Cuando ejecutas `df.to_excel(output_filepath, index=False)`, `pandas` intenta usar `openpyxl` en segundo plano para realizar la escritura, y si no lo encuentra, lanza ese error.

La advertencia previa que ves (`UserWarning: pandas only supports SQLAlchemy connectable...`) es solo eso, una advertencia. Te está indicando que `pandas` prefiere usar conexiones que sigan el estándar SQLAlchemy o sqlite3 para `read_sql_query`, pero que tu conexión `psycopg2` no es una de esas. Sin embargo, como el resto del código funciona (logras cargar los datos), puedes ignorar esa advertencia por ahora, ya que no es la causa de tu error de exportación.

-----

### Solución

La solución es simple: **instala el módulo `openpyxl`** en tu entorno virtual de Django.

1.  **Activa tu entorno virtual de Django.** Es crucial que instales `openpyxl` en el *mismo entorno virtual* donde está tu proyecto Django y donde tienes instalados `psycopg2` y `pandas`.

      * **Si estás en Windows:**
        ```bash
        cd C:\ESP_PYTHON_20250331\NIVEL_V\HENRY\curso\
        .\env\Scripts\activate  # Reemplaza 'env' con el nombre de tu entorno virtual si es diferente
        ```
      * **Si estás en macOS/Linux:**
        ```bash
        cd /ruta/a/tu/proyecto/django
        source env/bin/activate # Reemplaza 'env' con el nombre de tu entorno virtual si es diferente
        ```

    (Ajusta la ruta `C:\ESP_PYTHON_20250331\NIVEL_V\HENRY\curso\` y el nombre de tu entorno virtual según tu configuración).

2.  **Instala `openpyxl` usando `pip`:**

    ```bash
    pip install openpyxl
    ```

Una vez que `openpyxl` esté instalado, tu función `persona_exportar_excel` debería ejecutarse sin el error `No module named 'openpyxl'`. `pandas` lo detectará automáticamente y lo usará para escribir el archivo `.xlsx`.

def parse_line(line):
    """
    Parsea una sola línea del archivo de pagos utilizando posiciones de ancho fijo.
    Retorna un diccionario con los datos parseados y convertidos.
    """
    extracted_data = {}
    for field_name, (start, end) in FIELD_SLICES.items():
        # Asegurarse de que la línea sea lo suficientemente larga para el slice
        if len(line) > end:
            value = line[start:end].strip()
        else:
            value = '' # Asignar cadena vacía si la línea es demasiado corta
        extracted_data[field_name] = value

    # Inicializar el diccionario final con los campos del modelo PagoMovilRegistro
    parsed_record_data = {
        'tipo_de_operacion': extracted_data['banco_pagador_str'],
        'telf_pagador': extracted_data['telf_pagador_str'],
        'cod_receptor': extracted_data['banco_receptor_str'],
        'telf_receptor': extracted_data['telf_receptor_str'],
        'cuenta_pagadora': extracted_data['cuenta_pagadora_str'],
        'cuenta_receptora': extracted_data['cuenta_receptora_str'],
        'cod_transaccion': extracted_data['cod_transaccion_str'],
        'desc_transaccion': extracted_data['desc_transaccion_str'],
        'canal': extracted_data['canal_str'],
        'aplicativo': extracted_data['canal_str'], # Asumiendo que 'aplicativo' es lo mismo que 'canal'
        'monto_usd': None, # Se puede calcular si se tiene una tasa de cambio
        'auditoria': date.today(),
    }

    # Manejo de 'CEDULA PAGADOR' (cod_pagador y id_pagador)
    cedula_pagador_full = extracted_data['cedula_pagador_full_str']
    if len(cedula_pagador_full) > 0 and (cedula_pagador_full[0] in ['V', 'J']):
        parsed_record_data['cod_pagador'] = cedula_pagador_full[0]
        parsed_record_data['id_pagador'] = cedula_pagador_full[1:]
    else:
        parsed_record_data['cod_pagador'] = ''
        parsed_record_data['id_pagador'] = cedula_pagador_full # Si no hay prefijo, es el ID completo

    # Manejo de 'CEDULA RECEPTOR' (id_receptor)
    cedula_receptor_full = extracted_data['cedula_receptor_full_str']
    if len(cedula_receptor_full) > 0 and (cedula_receptor_full[0] in ['V', 'J']):
        parsed_record_data['id_receptor'] = cedula_receptor_full[1:]
    else:
        parsed_record_data['id_receptor'] = cedula_receptor_full # Si no hay prefijo, es el ID completo

    # Conversión de fecha
    try:
        parsed_record_data['fecha_tx'] = datetime.strptime(extracted_data['fecha_tx_str'], '%d-%m-%Y').date()
    except ValueError:
        parsed_record_data['fecha_tx'] = None # O manejar con una fecha por defecto o loguear

    # Conversión de hora
    try:
        parsed_record_data['hora_tx'] = datetime.strptime(extracted_data['hora_tx_str'], '%H:%M:%S').time()
    except ValueError:
        parsed_record_data['hora_tx'] = None # O manejar con una hora por defecto o loguear

    # Conversión de monto (maneja miles con punto y decimales con coma)
    try:
        monto_str_cleaned = extracted_data['monto_str'].replace('.', '').replace(',', '.')
        parsed_record_data['monto'] = float(monto_str_cleaned)
    except ValueError:
        parsed_record_data['monto'] = 0.0 # Valor por defecto en caso de error de conversión

    return parsed_record_data

    Lee un archivo plano de pagos móviles, parsea cada registro
    y lo inserta en la tabla `pago_movil` de PostgreSQL.

    file_path = 'C:/ESP_PYTHON_20250331/NIVEL_II/data/K40L410_250505.TXT'
    num_registros_insertados = 0
    mensaje = ''
    tipo = 1 # Tipo 1 para éxito, 2 para error (para la plantilla HTML)
    conn = None # Inicializa la conexión a None

    # --- Configuración de la base de datos ---
    # Asegúrate de que estos valores sean correctos para tu entorno PostgreSQL
    DB_HOST = "localhost"
    DB_NAME = "bd_nivel2_henry"
    DB_USER = "postgres"  # <--- CAMBIA ESTO por tu usuario de PostgreSQL
    DB_PASSWORD = "123456" # <--- CAMBIA ESTO por tu contraseña de PostgreSQL
    DB_PORT = "5432"

    try:

        if not os.path.exists(file_path):

        print(f"Conectándose a la base de datos '{DB_NAME}'...")
        conn = psycopg2.connect(
            host=DB_HOST,
            database=DB_NAME,
            user=DB_USER,
            password=DB_PASSWORD,
            port=DB_PORT
        )
        # Habilitar autocommit: cada sentencia SQL (INSERT) se confirmará automáticamente.
        # Esto previene el estado de "transacción abortada" si una inserción falla,
        # permitiendo que el resto de las inserciones continúen.
        conn.autocommit = True
        print("Conexión exitosa. Iniciando lectura y procesamiento del archivo...")

        # --- TRUNCAR LA TABLA ANTES DE LA INSERCIÓN ---
        with conn.cursor() as cur:
            print(f"Truncando la tabla 'pago_movil' en la base de datos '{DB_NAME}'...")
            cur.execute("TRUNCATE TABLE pago_movil;")
            # No es necesario conn.commit() después de TRUNCATE si autocommit es True
            print("Tabla 'pago_movil' truncada exitosamente.")

        # Leer todas las líneas del archivo
        with open(file_path, 'r', encoding='utf-8') as pago_movil_file:
            lista_registros_raw = pago_movil_file.readlines()

        print(f"Se encontraron {len(lista_registros_raw)} líneas en el archivo.")

        # Las primeras 6 líneas son cabeceras que deben ser ignoradas.
        # Las últimas líneas son resúmenes que también deben ser ignoradas.
        # Se asume que las líneas de datos comienzan en la línea 7 (índice 6).
        # Se filtran las líneas de pie de página por su contenido.
        data_lines = []
        skip_footer = False
        for line in lista_registros_raw[6:]: # Empezar desde el índice 6 (línea 7)
            stripped_line = line.strip()
            if stripped_line.startswith('TOTAL GENERAL') or \
               stripped_line.startswith('TRANSACCIONES PROCESADAS') or \
               stripped_line.startswith('TRANSACCIONES ACEPTADAS') or \
               stripped_line == '': # También ignorar líneas completamente vacías en el cuerpo del archivo
                skip_footer = True
                continue
            if not skip_footer:
                data_lines.append(line) # Añadir la línea original para el slicing

        print(f"Procesando {len(data_lines)} registros de datos válidos...")

        with conn.cursor() as cur: # Usar un cursor para ejecutar comandos SQL
            for i, registro_raw in enumerate(data_lines):
                # Usar la línea original (no stripped) para el parseo de ancho fijo
                # ya que los espacios iniciales son parte de la estructura fija.
                # Se limpia el strip() solo para el mensaje de log si es necesario.
                registro_limpio_para_log = registro_raw.strip()

                try:
                    parsed_data = parse_line(registro_raw) # Pasar la línea cruda para el slicing

                    # Construcción de la consulta SQL para INSERT
                    insert_query = """
                    INSERT INTO pago_movil (
                        tipo_de_operacion, cod_pagador, id_pagador, telf_pagador,
                        cod_receptor, id_receptor, telf_receptor, fecha_tx, hora_tx,
                        monto, cuenta_pagadora, cuenta_receptora, cod_transaccion,
                        desc_transaccion, aplicativo, canal, monto_usd, auditoria
                    ) VALUES (
                        %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s
                    );
                    """
                    # Tupla de valores a insertar, en el mismo orden que las columnas en INSERT INTO
                    values = (
                        parsed_data['tipo_de_operacion'],
                        parsed_data['cod_pagador'],
                        parsed_data['id_pagador'],
                        parsed_data['telf_pagador'],
                        parsed_data['cod_receptor'],
                        parsed_data['id_receptor'],
                        parsed_data['telf_receptor'],
                        parsed_data['fecha_tx'],
                        parsed_data['hora_tx'],
                        parsed_data['monto'],
                        parsed_data['cuenta_pagadora'],
                        parsed_data['cuenta_receptora'],
                        parsed_data['cod_transaccion'],
                        parsed_data['desc_transaccion'],
                        parsed_data['aplicativo'],
                        parsed_data['canal'],
                        parsed_data['monto_usd'],
                        parsed_data['auditoria']
                    )

                    # Ejecutar la inserción
                    cur.execute(insert_query, values)
                    num_registros_insertados += 1

                except (ValueError, IndexError, psycopg2.Error) as e:
                    # Captura errores de parseo (ValueError, IndexError) y de DB (psycopg2.Error)
                    print(f"Error procesando/insertando registro {i+1} ('{registro_limpio_para_log}'): {e}")
                    # Con autocommit=True, no se necesita rollback aquí para cada error de sentencia.
                    # La transacción para esta sentencia ya falló y fue manejada.
                    continue # Saltar al siguiente registro si hay un error

        mensaje = f"Carga de datos completada. Se insertaron {num_registros_insertados} registros en la tabla 'pago_movil'."
        print(mensaje)

    except FileNotFoundError as e:
        mensaje = f"Error: {e}"
        tipo = 2
        print(mensaje)
    except psycopg2.Error as e:
        # Este bloque captura errores de conexión a la base de datos o errores globales.
        mensaje = f"Error de base de datos durante la conexión o el procesamiento: {e}"
        tipo = 2
        print(mensaje)
        # Si la conexión no está en autocommit (aunque la habilitamos), un rollback es buena práctica
        # para asegurar que no queden transacciones pendientes en caso de errores de conexión.
        if conn and not conn.autocommit:
            conn.rollback()
    except Exception as e:
        # Captura cualquier otro error inesperado
        mensaje = f"Ocurrió un error inesperado: {e}"
        tipo = 2
        print(mensaje)
    finally:
        # Cerrar la conexión a la base de datos si se estableció
        if conn:
            conn.close()
            print("Conexión a la base de datos cerrada.")

    # Renderizar la plantilla HTML con el mensaje de resultado
    return render(request, 'index.html', {'mensaje':mensaje, 'tipo':tipo})
